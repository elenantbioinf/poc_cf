# poc_cf 

Proof of concept for an automated and reproducible genetic analysis workflow for cystic fibrosis (CF).

Master's Thesis — Universidad Internacional de Valencia (VIU).

**poc_cf** is a modular Snakemake-based pipeline designed as a proof of concept for automated analysis of CFTR variants from paired-end sequencing data.

The workflow follows reproducibility and FAIR principles by:

- Using a fully modular rule structure
- Managing dependencies through Conda environments
- Centralizing configuration in `config/config.yml`
- Separating production data from test datasets
- Providing a bootstrap initialization step

## Project initialization 

Before running the workflow, initialize the project structure:

```bash
./init.sh
```

This script reads directory paths from `config/config.yml` and creates the required base directories:
```bash
    data/
        clean/
        raw/
        reference/
    results/
    logs/
    visual/
    final_report/
```

## Requirements

This pipeline requires: 
- Linux or WSL2 environment
- Conda/Miniconda

Install the main environment with conda: 

```bash
    conda env create -f environment.yml
    conda activate poc_cf
```

With that action, Snakemake will be installed. Each rule automatically loads its own Conda environment during Snakemake execution.

## Input files

Input sequencing files are defined in: `config/samples.tsv`.

The input dataset must be placed in: `data/raw/`.

This pipeline was designed for **paired-end next-generation sequencing (NGS) data**.

In my own case: 

```bash
sample  fastq_1                     fastq_2
NA12878 data/raw/sample_R1.fastq.gz data/raw/sample_R2.fastq.gz
```

This pipeline takes the sample ID and the FASTQ paths from `samples.tsv`.

Before running the workflow, please modify this file according to your own dataset. 

## Configuration file

Pipeline parameters are defined in: `config/config.yml`

This file specifies directory paths, reference genome, target BED region, tool parameters, output directories. 
These parameters can be modified. 

## Running the pipeline

Execute the workflow with Snakemake by: 

```bash
snakemake --use-conda --cores 10
```

To know the workflow dependencies before execution: 

```bash
snakemake --dry-run
```

To visualize the workflow DAG: 
```bash
snakemake --dag | dot -Tpng > visual/dag.png
```

But you have an automatic generation of DAG in `visual/` directory when the pipeline finishes successfully.

## Pipeline overview

The workflow performs the following analysis steps by the Snakemake modules indicated:

1. Quality control of raw reads (FastQC, MultiQC) - `01_quality_control.smk`
2. Preprocessing and trimming (fastp) - `02_preprocessing.smk`
3. Reference genome download and indexing - `03_get_reference.smk`
4. Alignment to reference genome (BWA, samtools) - `04_mapping.smk`
5. Alignment quality control (samtools flagstat, Qualimap) - `05_quality_alignment.smk`
6. Add the read groups and duplicate marking (Picard) - `06_mark_duplicates.smk`
7. Coverage analysis on CFTR region (mosdepth) - `07_coverage.smk`
8. Variant calling (FreeBayes) - `08_variant_calling.smk`
9. Variant marking and filtering (bcftools) - `09_variant_filtering.smk`
10. Functional annotation using Ensembl VEP REST API – `10_annotation.smk`
11. Final report generation - `11_final_report.smk`
12. Final results visualization by web report generation (RMarkdown) - `12_web_report.smk`

## Outputs

The final outputs are generated in: `final_report/`.

Main outputs include:
- `sample.final_report.txt`
- `sample.final_report.json`
- `sample.web_report.html`

The HTML report provides a summary of detected variants in the CFTR gene.

## Reproducibility

This pipeline was designed to ensure reproducibility and portability across different computational environments.

Reproducibility is achieved through:

- **Snakemake workflow management**, which defines explicit input/output relationships between analysis steps.
- **Snakefile**, which defines the final output targets of the workflow..
- **Isolated Conda environments** for each module, ensuring consistent software versions.
- **Centralized configuration** in `config/config.yml`.
- **Explicit sample definition** using `config/samples.tsv`.
- **Automated project initialization** with `init.sh`.
